# Style Shelf 设计交接说明

## 目标

把当前项目重新设计为电脑端的本地 Web 创作工作台。每个 Skill 都应该被理解成一张独立的“风格工具卡”，用户从卡片进入对应的创作流程，而不是浏览手机相册或普通图片画廊。

## 当前进度

- 已搭建 React + Vite 前端工程。
- 已有四张 Skill 风格卡片：
  - `photo-abstract-editorial`
  - `gc-minimal-zine-poster-v0-1`
  - `scene-distillation-zine-v1-3`
  - `scenes-gathered-zine-v1-3`
- 四个首批 Skill 都使用可辨认的真实 Skill 产出图作为卡片封面；卡片图片框统一为 4:5。
- 新导入且没有样例的 Skill 显示“尚无真实样例”，不会再用色块伪装风格。
- 封面来源和 Job / Skill manifest 对应关系记录在 [COVER_PROVENANCE.md](./COVER_PROVENANCE.md)。
- 已实现桌面工作台骨架：左侧导航、中央风格卡片仓库、宽屏右侧任务与结果侧栏。
- 已实现模拟的创作工作区、任务进度、问题卡、结果图库和 Skill Workshop 入口。
- 已通过 `npm run build` 和浏览器交互检查。
- 设计阶段已完成；真实 Codex、Job 文件目录、上传复制和 Skill 安装链路仍未接入。

设计确认后已进入 Phase 2：本地结果服务、封面参数持久化、Job 创建、输入复制和状态文件已接入；真实 Codex Runner 和输出文件接纳仍未接入。

## 现象

上一版虽然已经改成桌面三栏结构，但视觉仍然偏“工具后台 + 卡片列表”，没有充分表达“每个 Skill 就是一张独立风格卡”的核心产品感。此前还出现过手机相册式的排版，这个方向已经被否定。

## 设计调整要求

### 1. 产品定位

- 这是电脑端 Web 应用，不是手机相册、图片瀑布流或普通素材管理器。
- 它是一个个人的“风格滤镜工作台”。
- Skill 卡片是进入创作能力的入口，不是单纯展示图片的图库卡片。
- 页面需要让人一眼看出：可以选择风格、进入创作、查看任务、管理结果和管理 Skill。

### 2. 桌面信息架构

保留并强化这个桌面结构：

```text
┌────────────────────────────────────────────────────────┐
│ 顶部：产品名 / 本地运行状态 / Codex 状态 / 添加 Skill │
├──────────────┬────────────────────────┬───────────────┤
│ 左侧导航     │ 中央主工作区            │ 右侧上下文栏  │
│              │ 风格卡片 / 创作工作区   │ 任务进度      │
│ 风格仓库     │ 结果图库 / 详情          │ 最近结果      │
│ 结果图库     │                        │ Skill 管理    │
│ 最近使用     │                        │               │
│ 收藏         │                        │               │
└──────────────┴────────────────────────┴───────────────┘
```

- 不能把首页做成全屏大标题加图片卡片。
- 不能让所有内容看起来像手机端卡片堆叠。
- 宽屏时必须体现中央工作区和右侧上下文栏的关系。
- 窄窗口可以收起右侧栏，但不能破坏桌面布局。

### 3. 风格卡片要求

每张卡片要有自己的视觉身份：

- 独立的色彩体系。
- 独立的构图或图像处理方式。
- Skill 名称、中英文名、输入类型、适用场景和版本信息。
- 明确的“打开工作区”动作。
- 卡片本身应该像一张风格工具样板，而不是通用的图片展示卡。
- 不要用四张相同的渐变占位图。
- 不要用同一种米色、纸张色或暖灰色铺满页面。
- 没有真实素材时可以占位，但占位必须诚实，并且不同 Skill 的色彩和构图仍要有区别。

### 4. 色彩要求

- 禁止以米色、奶油色、暖纸色作为全局页面底色。
- 页面 Chrome 使用冷灰白、蓝灰或中性浅灰。
- 风格卡片可以各自使用鲜明但克制的色彩，例如青绿、钴蓝、红色、紫色、荧光黄、深蓝等。
- 全局交互色只保留一个，卡片内部的风格色不受此限制。
- 不要使用紫色 AI 渐变、玻璃拟态或“科技仪表盘”作为默认答案。

### 5. 创作工作区要求

点击卡片后进入同一桌面框架内的 Creation Studio：

- 左侧导航保持不变。
- 中央区域显示当前 Skill 的输入方式。
- 右侧显示风格预览、参数摘要或任务上下文。
- 不同 Skill 的输入界面必须有差异：上传图片、文字输入、混合输入或问题卡。
- 不能统一做成一个“上传图片 + 提示词”的表单。

## 风险

- 现在仍是模拟任务，不能把模拟生成当作 Codex 链路已经接通。
- 新导入 Skill 如果仓库没有样例，必须先运行一次并保存结果，成功产出才会自动成为卡片封面。
- 设计重做时不要顺手改变产品信息架构和后端计划。
- 后续真实链路需要保留现有 Job、事件和本地存储边界。

## 建议

下一轮只重做前端视觉和交互结构，先不要接 Codex。建议先产出一张宽屏桌面主界面和一张 Creation Studio 状态，确认以下关系后再进入 Phase 2：

1. 风格卡片是否像独立 Skill 样板。
2. 桌面三栏是否像工作台而不是图库。
3. 中央创作区与右侧任务栏是否形成清晰关系。
4. 四张卡片是否有足够的视觉差异。
5. 页面在冷灰白背景下是否仍然有风格，而不是变成普通后台。

## 完成标准

- 用户打开页面后，第一眼理解这是桌面端风格创作工作台。
- 每张 Skill 卡片都具备可辨认的独立视觉身份。
- 首页不再像手机相册，也不再依赖统一米色背景。
- 点击卡片可以进入对应的创作工作区。
- 首次生成并保存结果后，无样例 Skill 自动获得真实产出封面。
- 宽屏下左侧导航、中央工作区和右侧任务上下文同时成立。
- 设计完成后仍能保留现有 React 工程和模拟交互，后续可以继续接真实 Codex 链路。
